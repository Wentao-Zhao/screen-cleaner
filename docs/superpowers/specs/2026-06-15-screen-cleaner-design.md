# 屏幕清洁设计规格

## 目标

创建一个仅支持 macOS 13 Ventura 及以上版本的菜单栏小工具。用户启动清洁模式后，应用阻止普通键盘输入和系统快捷键，所有显示器变为黑色，仅主显示器中央显示“退出清洁模式”按钮。用户使用鼠标点击该按钮后恢复正常状态。

## 应用形态

- 原生 SwiftUI + AppKit 应用。
- 常驻菜单栏，不显示 Dock 图标。
- 菜单栏图标为单色模板图标：显示器轮廓中放置一把向右上倾斜的小扫把。
- 扫把采用圆头长柄、横向连接座和三束宽刷毛的剪影结构，相对显示器内部可用空间缩小 20%。
- 应用包图标沿用“显示器 + 扫把”造型，使用白色到浅灰色背景，显示器缩小 10%，扫把再缩小 20%，并提供标准 macOS `.icns` 尺寸。
- 状态栏图标仅响应右键，菜单依次提供“开始屏幕清洁”、默认关闭的开机自启开关和“退出 App”。

## 清洁模式

1. 用户点击“开始屏幕清洁”。
2. 应用检查辅助功能权限。
3. 没有权限时不进入清洁模式，触发系统授权提示，并提供打开“隐私与安全性 > 辅助功能”的入口。
4. 有权限时，应用先创建全局键盘事件拦截。
5. 事件拦截成功后，为每个当前连接的显示器创建一个覆盖全屏的纯黑窗口。
6. 主显示器窗口中央显示“退出清洁模式”按钮，底部以低对比度显示“键盘输入已锁定”。
7. 其他显示器只显示纯黑背景。
8. 用户点击退出按钮后，先隐藏所有覆盖窗口，再停止键盘事件拦截并回到待机状态，菜单栏应用继续运行。
9. 覆盖窗口不调用 `close()`，隐藏后延迟释放，避免 AppKit 在窗口动画析构期间崩溃。

## 键盘拦截

- 使用 `CGEventTap` 监听并吞掉 `keyDown`、`keyUp`、`flagsChanged` 和 `systemDefined` 事件。
- F 区上的亮度、音量、Mission Control 等系统功能键可能以 `systemDefined` 事件进入，需要随普通键盘事件一起拦截。
- 本地打包使用稳定的 bundle identifier designated requirement，避免每次构建因 `CDHash` 改变而丢失辅助功能授权。
- 如果提供 Apple Development 或 Developer ID 证书，打包脚本优先使用指定证书签名。
- 保留鼠标移动和点击，使用户可以点击退出按钮。
- 事件 tap 因超时被系统禁用时，应用尝试立即重新启用。
- 电源键、Touch ID 和其他硬件级操作不属于普通应用可拦截范围。
- 应用意外退出时，系统会销毁事件 tap，不会永久锁定键盘。

## 多显示器行为

- 每次进入清洁模式时读取 `NSScreen.screens`。
- 所有显示器均创建黑色覆盖窗口。
- 以进入模式时的 `NSScreen.main` 作为主显示器，仅该窗口接收鼠标并显示退出按钮。
- 覆盖窗口位于屏幕保护程序级别，可跨 Space 显示，并覆盖菜单栏和 Dock。

## 状态与错误处理

应用状态包括：

- `idle`：等待开始。
- `needsPermission`：需要辅助功能权限。
- `starting`：正在建立键盘拦截和覆盖窗口。
- `active`：清洁模式已启用。
- `failed(message)`：事件 tap 或窗口创建失败。

事件 tap 创建失败时不得显示黑屏窗口。任何启动中途错误都要回滚已创建的资源。

## 测试

- 逻辑测试覆盖权限不足、事件拦截失败、成功启动、正常退出和资源回滚。
- 逻辑测试覆盖多显示器主屏选择策略。
- 逻辑测试覆盖状态栏仅右键交互、菜单项顺序和开机自启默认关闭。
- 生命周期冒烟测试覆盖隐藏并释放覆盖窗口后应用仍保持运行。
- 当前 Command Line Tools 不包含 XCTest/Swift Testing，使用独立测试可执行程序并运行 `swift run ScreenCleanerLogicTests` 验证逻辑。
- 运行 `swift build -c release` 验证 AppKit/SwiftUI 代码可编译。
- 运行打包脚本验证生成标准 `.app` 目录结构和 `Info.plist`。
